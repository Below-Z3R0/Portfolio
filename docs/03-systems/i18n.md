> **TL;DR:** El portfolio tiene **2 idiomas** (español + inglés) implementados vía **URL query param** (`?lang=en`). La elección persiste en la URL (no en cookies ni localStorage). El `LanguageToggle` es un `<Button>` que toggle entre `es` y `en` usando `useRouter().push()`. La tabla `languages` en la BD contiene los idiomas disponibles, y las traducciones se almacenan en `translations` con FK a `content_blocks` y `lang_code`. El idioma se pasa al orquestador (`getGeneralData(lang)`) que valida con Zod los bloques traducibles. **No hay fallback automático** si el `lang` no existe en la BD (la página rompe con throw).

## 🎯 Filosofía: URL-driven i18n (no cookies ni localStorage)

Elegimos URL query params sobre otros métodos por:

- **Shareable**: si comparto `?lang=en`, el receptor ve la versión en inglés.
- **SSR-friendly**: la URL está disponible en el servidor (`searchParams`).
- **Sin state global**: el idioma se infiere de la URL cada vez.
- **No hydration mismatch**: el cliente y servidor leen de la misma URL.

> **Tradeoff**: si el usuario cambia de idioma, la URL cambia (history entry). El back button puede confundir.

## 🗄️ Schema de la BD (tabla `languages`)

```sql
-- Tabla: languages
code        text  NOT NULL  PRIMARY KEY  -- "es", "en"
name        text  NOT NULL               -- "Español", "English"
is_default  bool  NULL  DEFAULT false  -- idioma por defecto
create_at   timestamptz NULL DEFAULT now()
```

**Limitación actual**: solo 2 idiomas (`es`, `en`). El `LanguageToggle` está **hardcoded** a estos 2 valores.

```

  ↓
Next.js Server Component (app/page.tsx)
  ↓ const currentLang = searchParams.lang || "es"
  ↓ const general_data = await getGeneralData(currentLang)
  ↓
getGeneralData("en")

  ↓   getData("section.hero", "es", ...)  ← solo cambia lang_code

    AND lang_code = "en"
  ↓
Retorna content jsonb (en inglés)
  ↓
Zod valida con HeroContentSchema
  ↓
Renderiza la home en inglés
  ↓
User hace click en LanguageToggle
  ↓ toggleLanguage()
  ↓   const newLang = currentLang === "es" ? "en" : "es"
  ↓   const params = new URLSearchParams(searchParams.toString())
  ↓   params.set("lang", newLang)
  ↓   router.push(`?${params.toString()}`)
  ↓
Browser: GET /?lang=es (o ?lang=en)
  ↓
Next.js hace Server Component rerender
  ↓
Hero en el nuevo idioma
```

## 🧩 LanguageToggle (27 líneas)

```tsx
"use client";
import { useRouter, useSearchParams } from "next/navigation";
import { LanguageIcon } from "../../services/assets/Icons";
import { Button } from "../components";

export function LanguageToggle() {
  const router = useRouter();
  const searchParams = useSearchParams();
  const currentLang = searchParams.get("lang") || "es";

  const toggleLanguage = () => {
    const newLang = currentLang === "es" ? "en" : "es";
    const params = new URLSearchParams(searchParams.toString());
    params.set("lang", newLang);
    router.push(`?${params.toString()}`);
  };

  return (
    <Button
      onClick={toggleLanguage}
      svg={"language"}
      buttonBody="size-7 z-50"
      svgStyle="text-foreground hover:text-primary"
    />
  );
}
```

**4 cosas clave**:
1. `useSearchParams` lee el lang actual de la URL.
2. `useRouter().push` cambia la URL.
3. Preserva otros query params (ej. si hay `?section=X&lang=es`).
4. **No hay re-render explícito** — Next.js detecta el cambio de URL y re-renderiza automáticamente.

### Por qué el icon es `LanguageIcon` directo (no vía `IconRender`)

```tsx
import { LanguageIcon } from "../../services/assets/Icons";
```

> El `IconRender` está para **iconos dinámicos** (donde el `name` viene de la BD o de un prop). En este caso, el ícono es **estático** (siempre el de language), así que importar el componente directo es más simple.

## 🛠️ Cómo agregar un nuevo idioma

### 1. Insertar el idioma en la BD

```sql
INSERT INTO portfolio.languages (code, name, is_default) VALUES
  ('pt', 'Português', false);
```

### 2. Para cada bloque traducible, insertar la traducción

```sql
INSERT INTO portfolio.translations (block_id, lang_code, content) VALUES
  ((SELECT id FROM content_blocks WHERE key = 'section.hero'),
   'pt',
   '{"title": "Olá", "contact": "Fale comigo", ...}');
```

> Esto hay que hacerlo por cada `content_blocks` que tenga texto.

### 3. Actualizar `LanguageToggle` para incluir el nuevo idioma

```ts
const SUPPORTED_LANGS = ["es", "en", "pt"] as const;
const newLang = SUPPORTED_LANGS[
  (SUPPORTED_LANGS.indexOf(currentLang as any) + 1) % SUPPORTED_LANGS.length
];
```

### 4. Actualizar `app/page.tsx` (si querés fallback)

```ts
const SUPPORTED_LANGS = ["es", "en", "pt"];
const currentLang = SUPPORTED_LANGS.includes(resolvedParams.lang as any)
  ? resolvedParams.lang
  : "es";
```

## ⚠️ Issues conocidas

### 1. **No hay fallback si el `lang` no existe en la BD**

```ts
// app/page.tsx
const currentLang = resolvedParams.lang || "es";
```

> Si `?lang=pt` (portugués) y no hay rows en `translations` con `lang_code="pt"`, el `getData` **falla con throw** (porque el query devuelve 0 rows + el `.single()` falla). La página rompe.

**Fix**: validar `lang` antes de llamar a `getGeneralData`.

```ts
const SUPPORTED_LANGS = ["es", "en"];  // ← cargado de la BD
const currentLang = SUPPORTED_LANGS.includes(resolvedParams.lang)
  ? resolvedParams.lang
  : "es";
```

> **Aún mejor**: cargar la lista de `SUPPORTED_LANGS` desde la tabla `languages` en la BD (no hardcodear).

### 2. **El `LanguageToggle` no muestra el idioma actual**

```tsx
<Button svg={"language"} buttonBody="size-7 z-50" svgStyle="..." />
```

> El botón **siempre** muestra el icono de language, sin importar el idioma actual. **Issue UX**: el usuario no sabe en qué idioma está sin ir a la URL.

**Fix**: cambiar el ícono según `currentLang`:
```tsx
svg={currentLang === "es" ? "language" : "language"}  // ambos, pero podríamos usar un flag
```
> Mejor: agregar íconos de banderas (Spanish flag, UK flag) o un `<span>` con `ES` / `EN`.

### 3. **El LanguageToggle preserva otros query params pero los reordena**

```ts
const params = new URLSearchParams(searchParams.toString());
params.set("lang", newLang);
router.push(`?${params.toString()}`);
```

> `URLSearchParams` **reordena los params alfabéticamente**. Si la URL era `?lang=es&section=Home`, queda `?lang=en&section=Home`. **Issue menor**: el back button puede confundir.

### 4. **No hay i18n en componentes UI**

Los textos hardcoded en componentes (ej. `"Cerrar"`, `"Reintentar"`, `"¡Mensaje enviado!"`) están **en español hardcoded**. **No se traducen con `lang`**.

**Fix planeado**: usar `next-intl` o `react-i18next` con un diccionario de strings UI:
```ts
const t = useTranslations("ErrorMessage");
return <h3>{t("title")}</h3>;  // "Algo salió mal" o "Something went wrong"
```

### 5. **El `lang` query param persiste a través de la navegación interna**

```tsx
router.push(`?${params.toString()}`);
```

> El usuario clickea un link `<a href="#Home">`. La URL no cambia (sigue siendo `?lang=en`). El idioma se preserva. **Bueno** (es lo que querés). **Issue**: si la URL tiene otros params (ej. `?section=contact&lang=en`), se preservan todos.

## 🔗 Conexiones con otros sistemas

- **DB + Supabase** — `lang_code` filtra las queries.
- **Orquestador** — `getGeneralData(lang)` pasa el idioma.
- **schemas.ts** — cada schema valida el `lang_code` indirectamente.
- **Theming v2** — el theme NO depende del idioma (ambos son independientes).
